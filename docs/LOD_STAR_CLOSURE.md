# LOD：STAR与研发轮次的闭环对应

2026-10-28。保留已确认的实际轮次，补齐任务目标、阶段验证和决策，不用四类能力分类替代研发过程。

## S / T

- **背景**：亿级场景需分块分级流式加载，有限带宽、点数与帧时间预算下，移动后模糊、换档卡顿与首屏状态不一致。
- **职责**：Viewer端调度、性能分析、离线资产粒度实验及预算验证；不把重建算法或引擎内部实现计为个人完成。
- **目标**：缩短当前视野细节等待、降低无效运行时工作、控制精度与速度取舍，并能对标原始调度、做版本回归。
- **约束**：第一轮交付紧迫，先改善体验再补完整评测；原文2秒/5秒/60FPS等验收线仅是目标，当前未建立统一满足这些门槛的结果，不作为已实现指标。

## 最终R：对应目标，而非只汇总技术名词

1. **运行时目标**：阶段CPU采样支持重复工作减少；不能将其表述为同等比例FPS增长。
2. **场景适配目标**：叶块数量影响管理成本，粗细取舍由点位恢复速度共同判断；不承诺同画质或越粗越好。
3. **加载/精度配置目标**：给出南广场预算实验的速度、帧率与实际点数，以此说明配置选择的依据；不把桌面数据替代移动端实测。
4. **可验证性目标**：形成原始基线对标、正确性检查、单变量实验及回归流程。

已收敛的是调度修复、可选策略取舍与默认配置；当前HEAD对官方基线的统一复测及部分场景尾部尖峰仍未完整闭环。首轮与OOF不补造独立收益数字。来源与提交核对沿用`LOD_NARRATIVE_CHRONOLOGY.md`及审计记录。
