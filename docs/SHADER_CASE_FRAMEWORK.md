## S｜背景与问题

平台需要在重建场景上配置画风、场景动态和开场动画。3DGS 缺少可直接依赖的面片法线；效果又分布在顶点修改、全屏后处理、独立几何等不同作用层。夜景、点彩、形变和开场争用单一 `gsplatModifyVS` 槽，切换与开场交接存在覆盖和状态残留风险。

来源：原文 §1.2–1.3。首层只保留约束和用户可感知问题，不堆完整效果目录。

## A1｜Composer 机制：让多个效果通过同一入口修改着色逻辑

**问题**：多个效果直接写着色槽，后写覆盖前写；一次性开场与夜景存在交接冲突。

**选择**：按作用层区分材质 chunk、unified work buffer、独立 Layer、全屏 post；共享着色修改经 Composer 合成与下发。贡献者声明作用域、优先级、独占和容量需求。分层片段按优先级组合；完整着色逻辑与分层逻辑不混排；冲突或容量不足输出诊断。

**结果与取舍**：把写入所有权和恢复责任从各效果隐含约定变成协议。一次性 reveal 整段接管时其他分层贡献让位；仍保留初始化顺序、独占与容量边界。结构 signature 与逐帧 uniform 更新分开，避免无意义重编译。

来源：原文 §3.1–3.2；当前本地 `gsplat-effect-composer.ts`、`gsplat-contribution.ts`。原文 NightMode 的 full / layered 叙述存在矛盾，页面不直接照抄精确兼容矩阵。

页面：`article#shader-ownership`；重光照引用此处。

## A2｜风格化算法：用方向场与投影补偿实现钢笔和点彩

**问题**：缺少面片法线，排线方向无直接几何依据；splat、全屏与天空的投影语义不同，点彩易出现点径和笔触不一致。

**选择**：钢笔使用图像结构张量提取方向，结合置信度回退、角度量化、加权模糊与分层排线；分析链使用 0.25 分辨率，主绘制全分辨率。点彩反算屏幕点径、用哈希抽稀，并做天空尺度补偿和后处理保护。

**结果与取舍**：形成图像后处理与 splat 混合两条路线。平坦区依赖回退方向，跨层点彩需联合调参；风格化避免改 center，波形位移仍存在排序边界。降分辨率属于成本控制设计，不写未经测量的性能收益。

来源：原文 §3.3、§4、§5.2。

展示：现有钢笔封面和用户指定的风格化链接；后续补同视角原图 / 结果、慢速运镜、点彩近远点径及天空边界。未声称已有视频覆盖这些验证镜头。

## A3｜开场生命周期：统一播放门控、着色交接与状态恢复

### 开场尺度适配与交接修复

**问题**：场景尺度改变传播范围，固定速度可能不能在目标时长内覆盖；内容提前放行暴露中间态；同帧卸载覆盖夜景恢复造成黑闪。

**选择**：bbox → 有效半径 → 速度与时长反算，统一完成谓词；首帧前装 Shader，完成后放行标注、资产、辉光与动画；卸载和恢复延后到 `frameend`。

**结果与取舍**：统一准备、接管、播放、完成和恢复生命周期，处理已定位的同帧覆盖路径。保留一帧交接延迟和初始化顺序约束，不承诺所有尺度零黑闪。一次性 sketch 与常驻 pen-sketch 分开说明。

来源：原文 §3.6、§4、§5.1。

展示：页面顺序图；补跨尺度播放计时与结束前后逐帧录屏。

### 渲染状态恢复与后端适配

卸载时恢复 chunk、Layer、背景色、曝光、雾与自动渲染等状态。全屏滤镜主要共用 GLSL 经引擎转译，点彩 splat / PS / 天空路径分别适配 GLSL 与 WGSL。配置持久化、播放定位与导出工作流另归编辑模式专题。
